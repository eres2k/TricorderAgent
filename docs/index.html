A real agent that never leaves your machine.

Not a chat window with a local model behind it. Tricorder Agent reads and writes files, runs shell commands, drives a headless browser, executes code in a sandbox, plans its own work and spawns sub-agents — at ~100 tokens/sec, with zero dependencies and nothing phoning home.

Installed in one command

No npm install, no build step, no dependency tree to keep working. The runtime is Node's standard library and vanilla browser JS — clone it and start it.

Every run after the first goes straight to the server. npm run setup redoes the detection whenever you want it.

What the first run does for you~2 min
  1. Checks the host — Node version, memory budget, and which optional extras (Docker, Chromium, Python) you already have.
  2. Sizes the model — works out which quant and context window actually fit your memory, and prints the command to serve it.
  3. Finds the backend — probes LM Studio, llama.cpp and Ollama, then ranks what's loaded.
  4. Proves it works — sends a real request to confirm the model can call a tool, reason at depth, and see an image.
  5. Writes the config — merges into .env rather than overwriting, then creates the workspace and boots.

What a turn looks like

Not a mockup — the actual app, mid-task.

The interesting part runs while you sleep

Ask for something recurring in plain language. It becomes a scheduled task using the same tools, and the same approval rules, as a live conversation.

“Every weekday at 07:00, pull the overnight CI failures from my repos, group them by which test broke, and email me the summary.”

One task doing five things: a schedule, a multi-step tool chain, its own judgement about grouping, a written artifact, and delivery. It runs whether or not the browser is open.

Fixed schedule cron

Every weekday at 07:00, the 1st of the month, every four hours. Ordinary recurring work, described in words rather than crontab syntax.

Until a condition holds smart

“Check every 20 minutes until the deploy is green, then tell me.” It re-checks, reports progress, and deletes itself the moment the condition is true — a watchdog you have to clean up afterwards is a bug.

Delivered to you smtp

Results arrive by email with attachments, or as a file, or waiting in the chat. Restrict the agent to your own address and a scheduled task can never mail a stranger.

Against the alternatives

Two things usually trade off: a cloud assistant gets real tools but your data leaves the building; a local chat UI keeps the data but can only talk. This build refuses the trade.

The fine print

What the numbers do and don't claim.

On the throughput figure
~100 tok/s is Qwen3.8-27B at Q4_K_M on an RTX 5090 with the MTP draft model enabled. It is hardware-bound: a smaller GPU is slower, CPU inference much slower. Your machine is the variable, not the software.
On the comparison
Columns are categories, not named products, because capabilities inside each category vary and move quickly. "Varies" means exactly that — check the specific tool you are weighing this against.
On "nothing leaves your machine"
No telemetry, no analytics, no update pings — verified by audit of the source. Outbound requests happen only when a tool you invoked makes one: a web search, a page fetch, a model download.
On the sharp edges
This is an agent with a shell on your machine. Files are sandboxed to a workspace, credential files are refused, and there is no login until you set one. Set a password before exposing it beyond localhost.
